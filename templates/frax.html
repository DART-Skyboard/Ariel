About .frax▾
FRAX stands for Fraxinus Raster Array Exchange.

Named after Fraxinus — the scientific genus of the Ash tree. The Ash Tree is the root metaphor of the DART Meadow ecosystem:
🌳 ASH TREE ECOSYSTEM
 ├─ .ash Project & app data
 ├─ .leaf Documentation & info
 └─ .frax Raster imagery

Where .ash carries full project state and .leaf holds docs, .frax is the visual layer — a raster image interchange format built for the entire DART Meadow suite.

Extensible channel architecture supports depth maps, HDR, thermal/CFD fields, and custom scientific data alongside standard RGBA — all in one file.

Ch TypesR=1 G=2 B=3 A=4 L=5 D=6 H=7 X=8
Compress0=Raw 1=RLE 2=Deflate
Bit Depthuint8 (8 or 16)
Metadatauint32 len → UTF-8 JSON
DataPer-ch lengths → compressed arrays
Metadata JSON carries arbitrary data — source app, timestamps, render settings, AR anchors, alloy specs, etc.
How It Works▾
Encode: Pixels split into separate channel planes. Each plane is a flat uint8 or uint16 array of W×H values, compressed independently via Raw, RLE, or Deflate. Binary header packs metadata + per-channel data blocks.

Decode: Header parsed for dimensions, channels, compression. Each block inflated to flat array. Channels recombined to RGBA for display or re-export.

Why per-channel separation? Individual channels compress better than interleaved RGBA. Enables selective extraction — pull just depth or alpha without touching color. Future channels extend without breaking backward compat.

Channel Types▾
R = 1Red
G = 2Green
B = 3Blue
A = 4Alpha / transparency
L = 5Luminance (grayscale)
D = 6Depth buffer
H = 7HDR
X = 8Custom (app-defined)
D, H, X are reserved for ecosystem extensions — AR depth, CFD thermal, spectral chemistry, or any scalar field.
